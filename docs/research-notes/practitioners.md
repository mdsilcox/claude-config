# Practitioner practices for configuring and working with Claude Code (state as of 2026-10-24)

**Lens and how to read the tags.** This file covers what heavy Claude Code users actually do and report, not official guidance (another researcher covers Anthropic docs; where I cross-check the docs I say so). Evidence tags: [first-hand, detailed] = a practitioner describing their own setup with specifics; [first-hand, unmeasured] = same but results are self-reported; [vendor/author] = written by the tool's author or an Anthropic employee; [secondary] = aggregator, tutorial or summary of someone else; [anecdote] = a single forum comment; [study] = a measured benchmark. Dates are publication dates. "HN ~Mon YYYY" means the Hacker News page only showed a relative age when I fetched it on 2026-10-24, so the month is approximate. [OLD] = published before about 2026-04-24 (older than six months) and possibly superseded: Claude Code moved a lot since then (Tool Search for MCP, auto mode becoming the default in Aug 2026, native AGENTS.md reading in Sept 2026, newer model generations). Star counts and install numbers are popularity, not evidence of quality. Reddit was blocked for my search tool, so r/ClaudeAI and r/ClaudeCode are not directly covered. I paraphrase sources rather than quote them.

## 1. What do credible practitioners keep in global and project CLAUDE.md, and how long are the files (including short vs long evidence)?

### Takeaway
Credible voices converge on a short root file (roughly 60 to 200 lines, or about 1k tokens by the Claude Code creator's own advice) holding only what the agent cannot infer, grown from repeated observed mistakes rather than written up front, with the global file an even shorter list of behavior preferences. Dissent exists: a team monorepo file of 13 KB, a user reporting 10k tokens working fine, an Anthropic engineer saying to start projects with no file at all, and two 2026 studies showing context files can add cost without gains.

### Cited Findings

#### Length targets
- Anthropic's current memory docs (cross-check, fetched 2026-10-24): target under 200 lines per CLAUDE.md because longer files cost context and reduce adherence; `@` imports organize a file but do not reduce its context cost; path-scoped `.claude/rules/` is the way to keep rules for part of a codebase out of every session; CLAUDE.md is context, not enforcement, so use a PreToolUse hook to block actions | [Claude Code docs: memory](https://code.claude.com/docs/en/memory) [vendor/author]
- Boris Cherny (Claude Code creator), HN comment (HN ~Dec 2025 [OLD]): keep CLAUDE.md under about 1k tokens; his own is about half that and gets trimmed with each model release; split big content into smaller linked files or nested directories | [HN item 46256606](https://news.ycombinator.com/item?id=46256606) [vendor/author]
- A Brazilian write-up says Cherny's personal CLAUDE.md is two lines (turn on automerge when opening a PR; post to the team Slack channel when opening a PR), layered on a much larger shared team file in the Claude Code repo | [TabNews](https://www.tabnews.com.br/kenimo49/o-criador-do-claude-md-escreve-2-linhas-a-comunidade-escreve-100-quem-esta-errado) [secondary, undated, single author, not verified against Cherny]
- HumanLayer (Kyle, 2025-11-25 [OLD]): keep under about 300 lines, shorter is better, their own root file is under 60 lines; frontier models follow roughly 150 to 200 instructions reliably and Claude Code's own system prompt already uses about 50 of them (author's estimate) | [HumanLayer blog](https://www.humanlayer.dev/blog/writing-a-good-claude-md) [first-hand, unmeasured]
- A solo developer's three-way test on a Next.js/TypeScript/Prisma project (undated, roughly mid-2026): 2 lines meant Claude repeated mistakes (about 4 minutes lost per session); 247 lines meant a key rule in the middle was ignored and stale rules contradicted each other; a 67-line version with critical rules first, detail moved to referenced files and formatting left to a linter worked best; recommends 50 to 80 lines for solo projects | [TabNews](https://www.tabnews.com.br/kenimo49/o-criador-do-claude-md-escreve-2-linhas-a-comunidade-escreve-100-quem-esta-errado) [anecdote]
- Alex Kras cut CLAUDE.md from 246 to 123 lines and skills from 24 to 9 on 2026-09-04, measuring with `/context all` before and after; the largest gains came from CLAUDE.md and skill descriptions, not from MCP tools as he expected | [alexkras.com](https://alexkras.com/i-deleted-24-claude-code-skills-and-only-9-came-back/) [first-hand, detailed]
- A vault-root CLAUDE.md of about 106 lines with its own rule to keep files under 150 lines, updated roughly weekly (post undated; install commands re-checked on 2026-08-01) | [okhlopkov.com](https://www.okhlopkov.com/claude-code-setup-mcp-hooks-skills-2026/) [first-hand, detailed for the excerpt; the rest of the post is generic explainer]
- Dissent on length: Shrivu Shankar's work monorepo file is about 13 KB and may reach 25 KB, but it only covers tools used by roughly 30 percent or more of engineers and gives each internal tool a token budget; a fresh session there costs about 20k of the 200k window (2025-11-02 [OLD]) | [sshh.io](https://blog.sshh.io/p/how-i-use-every-claude-code-feature) [first-hand, detailed]. On HN, xpe reports about 10k tokens of guidelines working well while doubting anyone has studied it rigorously (HN ~Dec 2025 [OLD]) | [HN item 46098838](https://news.ycombinator.com/item?id=46098838) [anecdote]

#### What goes in, what stays out
- HumanLayer: include WHAT (stack, structure map), WHY (purpose of the parts) and HOW (package manager, how to verify with tests, typecheck and build). Leave out exhaustive command lists, style guides, task-specific instructions, one-off hotfix rules and code snippets that go stale. Point to real code by file and line, use progressive disclosure through an `agent_docs/` folder, do not auto-generate the file with `/init`, and enforce style with a formatter or linter in a Stop hook (2025-11-25 [OLD]) | [HumanLayer blog](https://www.humanlayer.dev/blog/writing-a-good-claude-md)
- arps18 (2026-05-26): keep build and test commands Claude cannot guess, the order to run them and a Gotchas section; avoid standard language conventions, file-by-file tours, tutorials, API docs and fast-changing detail; use emphasis words sparingly | [arps18 post](https://arps18.github.io/posts/claude-code-mastery/) [first-hand, mostly generic]
- Shrivu (2025-11-02 [OLD]): point to docs with a stated reason to read them instead of `@`-importing them; offer alternatives rather than bare never-rules; hobby projects let Claude write whatever it wants | [sshh.io](https://blog.sshh.io/p/how-i-use-every-claude-code-feature)
- Mitchell Hashimoto (2026-02-05 [OLD]): each AGENTS.md line targets one observed bad behavior (wrong commands, wrong APIs); he pairs lines with small scripts (screenshots, filtered test runs) that the agent is told exist; he links Ghostty's nested `src/inspector/AGENTS.md` as an example | [mitchellh.com](https://mitchellh.com/writing/my-ai-adoption-journey) [first-hand, detailed]
- Rules that must hold belong in hooks or permissions, not prose: rkuska keeps commit rules in CLAUDE.md but also runs the checks in pre-commit hooks because agents skip steps; hipvlady says only `permissions.deny` reliably enforces anything and that subagents may not apply CLAUDE.md discipline (HN ~May 2026) | [HN item 48289950](https://news.ycombinator.com/item?id=48289950) [anecdote]
- Compliance complaints on HN (~Dec 2025 [OLD]): longer files get fewer directions followed (nico); instructions are followed at the start and end of a conversation but ignored in the middle (chickensong); referenced files are rarely read when CLAUDE.md is only a table of contents (sothatsit, Sammi); Codex with AGENTS.md follows rules more literally (pmarreck); lostdog finds `/init` output too wordy to be useful | [HN item 46098838](https://news.ycombinator.com/item?id=46098838) [anecdote]

#### Maintenance habit (the strongest point of agreement)
- Cherny's team keeps one shared CLAUDE.md in git, adds a rule whenever Claude makes a mistake, and tags Claude on PRs to add rules (thread of 2026-01-02 [OLD]) | [howborisusesclaudecode.com](https://howborisusesclaudecode.com) [secondary aggregator of his threads]. He said in the HN comment that he adds to the team file several times a week | [HN item 46256606](https://news.ycombinator.com/item?id=46256606)
- leek.io's published global file (2026-06-17, modified 2026-10-06): add a rule only after the same mistake has happened at least twice; keep rules general, not tied to one incident; prune rules that have not earned their keep within about a month; start from an empty file. Categories: working relationship (ask one sharp question only when truly ambiguous, do what was asked, do not widen scope to unrelated failing tests), git hygiene (stage by explicit path, check status, re-check HEAD against the remote before rewriting history), destructive operations need approval, verification (confirm an identifier exists before using it), testing taste (test behavior and persisted data, not framework behavior or copy and CSS), reuse before building (reuse, extend, extract, configure, plug in, only then write new code); a 600-line global file would be a real per-session cost | [leek.io](https://leek.io/articles/my-global-claude-md-rules) [first-hand, detailed]
- Thariq Shihipar of the Claude Code team (Latent Space, 2026-09-29): CLAUDE.md may eventually disappear; start new projects without one, add entries only for repeated failure modes, and expect the right content to vary by model | [Latent Space](https://www.latent.space/p/thariq) [vendor/author]
- Cherny's tips page reports that about 80 percent of Claude Code's system prompt was removed for the newest models with no measurable eval loss, and describes a `/checkup` command that dedupes CLAUDE.md and splits a large root file into nested ones (the file had been loading about 10k tokens per session; about 5.5k saved) | [howborisusesclaudecode.com](https://howborisusesclaudecode.com) [secondary; vendor claim]. The docs add `/doctor prompt-audit` (v2.1.283 or later) to flag instructions written for older models and contradictory rules | [Claude Code docs: memory](https://code.claude.com/docs/en/memory)
- EGreg (HN ~May 2026): letting Claude write rules for itself after mistakes is the highest-return habit, but CLAUDE.md is not a containment layer | [HN item 48289950](https://news.ycombinator.com/item?id=48289950) [anecdote]
- Even a widely shared workflow post (Boris Tane, 2026-02-11 [OLD]) does not mention a CLAUDE.md at all; his artifacts are research.md and plan.md | [boristane.com](https://boristane.com/blog/how-i-use-claude-code/)

#### Evidence on short vs long (benchmark studies, not side-by-side on real projects)
- ETH Zurich / LogicStar (arXiv, Feb 2026 [OLD]): across several coding agents and models, repository context files gave no improvement in task success and raised inference cost by over 20 percent; LLM-generated files added about 3.92 steps per task and about 23 percent cost; conclusion: human-written files should describe only minimal requirements. The ICLR version words it as context files tending to reduce success. A secondary summary puts human-written files at about +4 percent and LLM-generated at about -2 percent | [arXiv 2602.11988](https://arxiv.org/abs/2602.11988); [AI Weekly summary](https://aiweekly.co/alerts/paper-finds-agentsmd-files-hurt-coding-agent-task-success); [DAIR.AI summary](https://academy.dair.ai/papers/evaluating-agents-md) [study; the +4 and -2 figures come from secondary summaries I did not trace to the paper's tables]
- Vercel (Jan 2026 [OLD]): in their Next.js 16 evals a compressed 8 KB docs index placed in AGENTS.md reached a 100 percent pass rate, skills topped out at 79 percent even with explicit instructions to use them, and skills without such instructions did no better than no docs; a secondary write-up says the skill was never invoked in 56 percent of cases. Vercel's reading: always-on context removes the decision point; skills fit vertical, action-specific workflows | [Vercel blog](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals) [vendor eval on one framework; 56 percent figure is secondary]

### Inferences
- A defensible default for a solo developer is a project root file of about 50 to 120 lines (commands to run, test and lint; stack and layout map; how to verify; a Gotchas list; pointers to deeper docs) and a global file well under 50 lines of behavior preferences. The disagreement is mostly about scale (team monorepos justify more) and model vintage (Anthropic staff in Sept 2026 lean toward less, and rules written for older models become dead weight).
- ETH and Vercel pull in different directions; the reconciling variable is content type. Passive context helps for facts the model lacks (new APIs, local commands, non-obvious gotchas); repository overviews and generic advice it can discover on its own cost tokens and extra steps.
- Treat every rule as a failure-log entry and schedule a prune pass at each model generation (the docs' `/doctor prompt-audit` does part of this).
- For this user's stack, recording which environment (Windows host or the Ubuntu VM) runs tests and the shell differences is a plausible gotcha entry; I found no source on it, so that is my inference.

### Gaps
- No controlled side-by-side of short vs long CLAUDE.md on real (non-benchmark) projects; only anecdotes (TabNews test, Kras) and two benchmark studies on Python and Next.js tasks.
- Could not verify the two-line Cherny file from a primary source.
- Did not open public example global files (for example czottmann/claude-code-stuff, abhishekray07/claude-md-templates) beyond the leek.io write-up.
- No practitioner write-ups found for C++ or C# game-mod projects, or for FastAPI plus HTMX specifically.
- Reddit not reachable.

## 2. Which hooks, skills, MCP servers and plugins are called genuinely valuable, and which do people uninstall as noise?

### Takeaway
Hooks that enforce something deterministic (formatter after edit, block destructive or secret-touching commands, gate commit or stop on tests) are the most consistently praised. MCP use has shrunk to a few servers (docs lookup, browser verification, team services) with CLIs preferred for tools the model already knows, though the 2025 argument that MCP burns context weakened in 2026. Skills are liked when few, small and well described but contested as an abstraction; plugins draw the most noise complaints (LSP, code review, big bundles). Pruning by measurement (`/context all`) is the recurring tactic.

### Cited Findings

#### Hooks
- Cherny (2026-01-02 [OLD]): a PostToolUse hook runs the formatter after Claude edits so formatting edge cases do not fail CI; a Stop hook or background verifier does deterministic checks on long jobs; a shared pre-allowed command list lives in `.claude/settings.json` through `/permissions` instead of skipping permissions | [howborisusesclaudecode.com](https://howborisusesclaudecode.com) [secondary aggregator]
- Shrivu (2025-11-02 [OLD]): a PreToolUse hook on `git commit` blocks the commit unless a test script has written a pass-marker file, forcing a test-and-fix loop; plus non-blocking hint hooks; he avoids blocking hooks on Edit or Write because blocking mid-plan confuses the agent | [sshh.io](https://blog.sshh.io/p/how-i-use-every-claude-code-feature) [first-hand, detailed]
- Ian Paterson (2026-03-25, updated 2026-08-15): hooks on EnterPlanMode (inject his plan template; compliance rose from about 70 to 100 percent, self-reported), WebFetch (prompt-injection warning), Bash (safety checks in infrastructure directories) and Write/Edit (lint reminder) | [ianlpaterson.com](https://ianlpaterson.com/blog/stop-claude-code-from-lobotomizing-itself-mid-task/) [first-hand, unmeasured]
- okhlopkov: a pre-commit hook script blocks commits that stage `.env`, `.key`, `.pem` files or files named creds.md | [okhlopkov.com](https://www.okhlopkov.com/claude-code-setup-mcp-hooks-skills-2026/) [first-hand]
- HN (~Dec 2025 [OLD]): MarkMarine and brianwawok use hooks to block or enforce actions rather than tuning CLAUDE.md | [HN item 46098838](https://news.ycombinator.com/item?id=46098838) [anecdote]
- Jesse Vincent (2026-10-05): after AI colleagues merged a PR to main despite objections posted in Slack and draft status, he recommends enforcement by the system: branch protection and required checks, tokens that cannot merge or push to protected branches, and agent-level permission deny rules or pre-tool hooks that block merging PRs or pushing to main; chat messages and draft status are not gates | [blog.fsck.com](https://blog.fsck.com/2026/10/05/today-at-work/) [first-hand, detailed incident]
- Limits: one write-up shows a proof of concept where an agent still exposed `.env` contents despite blocking hooks, because hooks intercept individual tool calls and cannot remove secrets already in context; it recommends layering isolation | [CodeOnGrass](https://codeongrass.com/blog/claude-code-pretooluse-hooks-bypass-blast-radius/) [secondary]
- The official Ralph loop plugin is implemented as a Stop hook with an iteration limit; the hook input carries a `stop_hook_active` flag to avoid endless loops | [The Register, 2026-01-27](https://www.theregister.com/2026/01/27/ralph_wiggum_claude_loops/); [hooks docs](https://docs.anthropic.com/en/docs/claude-code/hooks) [secondary; vendor docs]

#### Skills
- Matt Pocock's skills repo is the best-known small-skills collection: user-invoked, composable, no execution layer; the flagship `grill-me` interviews you one question at a time with a recommended answer for each and refuses to implement until you agree (reports of 50 or more questions); the README frames heavier systems as taking control from the engineer | [Implicator](https://www.implicator.ai/matt-pocock-skills-repo-jumps-past-45k-stars-with-reusable-ai-instructions/); [DEV review](https://dev.to/yimtheppariyapol/mattpocockskills-review-a-real-engineers-claude-160k-stars-4d3f) [secondary; star counts vary from 45k in Apr 2026 to 160k later]
- arps18 (2026-05-26): a skill is a folder with SKILL.md; only frontmatter descriptions load at session start so skills stay cheap until they fire; set `disable-model-invocation: true` for skills with side effects; prefer `skills/` over loose command files; turn anything repeated more than once a day into a skill and check them into git | [arps18 post](https://arps18.github.io/posts/claude-code-mastery/)
- Description-only cost is small: one HN user lists 12 installed skills at roughly 90 to 300 tokens each (HN ~Jun 2026) | [HN item 48421406](https://news.ycombinator.com/item?id=48421406) [anecdote]
- Reliability concern: in Vercel's evals the model often never invoked the skill (see Section 1) | [Vercel blog](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)
- Pruning: Kras deleted 24 skills and restored only 9 as needed (2026-09-04) | [alexkras.com](https://alexkras.com/i-deleted-24-claude-code-skills-and-only-9-came-back/). Cherny's tips page cites 38 unused project skills across 2,345 sessions in one analysis | [howborisusesclaudecode.com](https://howborisusesclaudecode.com) [secondary, context unclear]
- Disagreement (HN ~May 2026): superfrank calls skills a bad abstraction and unshavedyak says they are just more tokens; amazingman calls them poorly defined workflows; chris_money202 says MCPs, skills and plugins are all noise and that naming the CLI in the prompt is enough; binarymax and wonkyfruit defend skills; cheema33 says lacking skills uses more tokens; Majromax says clean-context subagents lower cost | [HN item 48289950](https://news.ycombinator.com/item?id=48289950) [anecdotes]
- Thariq (2026-09-29): skills can now be evaluated for whether they actually help; he likes a short explain-it-simply skill | [Latent Space](https://www.latent.space/p/thariq) [vendor/author]

#### MCP servers
- Kept: Context7 for docs (one HN user's near-vanilla setup, HN ~Jun 2026; also in arps18's starter set of GitHub, Context7 and one or two domain servers, 2026-05-26); Playwright for seeing front-end work (Shrivu says it is the only MCP he kept, 2025-11-02 [OLD]; kingkongjaffa, HN ~May 2026); Coolify and a Telegram bridge plus a Codex MCP for second-model plan review (okhlopkov); Slack and Sentry on Cherny's team (2026-01-02 [OLD]) | [HN item 48421406](https://news.ycombinator.com/item?id=48421406); [arps18 post](https://arps18.github.io/posts/claude-code-mastery/); [sshh.io](https://blog.sshh.io/p/how-i-use-every-claude-code-feature); [okhlopkov.com](https://www.okhlopkov.com/claude-code-setup-mcp-hooks-skills-2026/); [howborisusesclaudecode.com](https://howborisusesclaudecode.com)
- Dropped for CLIs: Cherny uses the `bq` CLI; Shrivu has mostly replaced MCP with CLIs and scripts [OLD]; Tane uses no MCP (2026-02-11 [OLD]); Simon Willison tried the Cloudflare MCP and went back to the Cloudflare API when the MCP could not edit rules (2026-06-16) | [simonwillison.net tag page](https://simonwillison.net/tags/claude-code/); [boristane.com](https://boristane.com/blog/how-i-use-claude-code/)
- The context-cost argument weakened: GitHub issue #11364 (2025-11-10 [OLD]) measured seven MCP servers at about 67.3k tokens of tool definitions before any prompt; Claude Code's Tool Search (v2.1.7) defers MCP definitions by default once they would exceed 10 percent of context, and Anthropic claims an 85 percent cut in definition tokens | [mcp.directory](https://mcp.directory/blog/mcp-context-bloat-fix-2026-tool-search-code-mode-progressive-disclosure) [secondary, page updated May 2026]. Checkly ran one Playwright task three times in fresh Claude Code sessions (2026-07-30) and got about 48k to 50k tokens of context via MCP vs 45k to 48k via CLI, concluding the CLI-is-cheaper advice has aged out; it still favors CLIs for tools the model already knows such as `gh` | [Checkly](https://www.checklyhq.com/blog/mcp-vs-cli-token-efficiency/) [first-hand, small sample]. Benchmarks around the February 2026 Playwright CLI launch had reported about 114k vs 27k tokens per task | [Morph](https://morphllm.com/playwright-mcp) [secondary, vendor-adjacent, older]; a later DEV Community re-benchmark on newer versions reportedly found the gap near 1 percent | [DEV Community](https://dev.to/aswani25/playwright-cli-vs-playwright-mcp-which-should-you-use-with-claude-code-1olh) [secondary, attribution taken from a search summary]
- Armin Ronacher (2026-10-06, in his Pi harness, not Claude Code) exposes MCP tools only through a search inside a sandboxed JavaScript codemode instead of listing them in the prompt, and argues bash alone cannot cover harness-native features such as images or subagents | [lucumr.pocoo.org](https://lucumr.pocoo.org/2026/10/6/codemode/) [first-hand]. His 2025 advice, as summarized by Simon, was to write a script or Makefile target the agent can run instead of an MCP | [simonwillison.net](https://simonwillison.net/2025/Jun/29/agentic-coding/) [OLD]

#### Plugins
- Superpowers is described by its author as the top third-party Claude Code plugin with over 1.1 million installs (2026-10-09) | [blog.fsck.com](https://blog.fsck.com/2026/10/09/what-a-year/) [vendor/author]
- LSP plugin is a clear split: arps18 calls it the highest-leverage plugin (symbol navigation and on-edit diagnostics); mil22 on HN found the LSP tool invoked once across hundreds of sessions, and over 627 sessions the Python LSP injected diagnostics in 186 sessions with 33 findings, only 1 acted on, so uninstalled (HN ~May 2026) | [arps18 post](https://arps18.github.io/posts/claude-code-mastery/); [HN item 48289950](https://news.ycombinator.com/item?id=48289950)
- `/code-review`: extr recommends it; sdevonoes and bix6 see nothing beyond plain prompting; Cherny says `/code-review ultra` costs $3 to $20 per run and the built-in skill will be the consolidated path; 8note's three runs found typos, then six items with targeted prompting, then nothing; commenters note the plugin mostly packages skills and subagents you could write yourself (HN ~May 2026) | [HN item 48289950](https://news.ycombinator.com/item?id=48289950) [anecdotes plus vendor comment]
- arps18 names `/code-review`, `/feature-dev` and `/security-guidance` as plugin starting points (2026-05-26); a near-vanilla HN setup lists only a frontend-design plugin, language-server plugins and Context7 (HN ~Jun 2026) | [arps18 post](https://arps18.github.io/posts/claude-code-mastery/); [HN item 48421406](https://news.ycombinator.com/item?id=48421406)
- Thariq (2026-09-29) describes Claude Code mods as the successor to function hooks: they run in-process, can spawn forked subagents (forks reuse the prompt cache) and change the UI; examples include a quiz after each task and a model router | [Latent Space](https://www.latent.space/p/thariq) [vendor/author]

#### Measure then prune
- Kras's method: back up `~/.claude`, run `/context all`, disable connectors that are enabled but unauthenticated (they still add tool names to context), delete unused skills, commands and plugins, restore only as needed, re-measure (Claude Code 2.1.252) | [alexkras.com](https://alexkras.com/i-deleted-24-claude-code-skills-and-only-9-came-back/)
- Start small and add one thing at a time: one CLAUDE.md, one MCP server, one hook, one skill, subagents only for isolated context (undated, checked Aug 2026) | [okhlopkov.com](https://www.okhlopkov.com/claude-code-setup-mcp-hooks-skills-2026/)

### Inferences
- The most-endorsed keep list across sources: a formatter or lint hook after edits, a PreToolUse hook that blocks destructive commands and secret access, a test gate on commit or Stop, one docs MCP (Context7), one browser verification path (Playwright MCP or CLI, or the Chrome extension), `gh` instead of a GitHub MCP, and a handful of hand-written skills for repeated workflows.
- Noise candidates: LSP plugin (contested), broad plugin bundles, long lists of custom slash commands (Shrivu), unauthenticated connectors, MCP servers duplicated by a CLI the model already knows.
- Hooks are bash-centric in every source; I found nothing on writing them for native Windows PowerShell, which matters for a Windows host. Running hooks and risky autonomy inside the Ubuntu VM sidesteps that, but that is my inference.
- The basic-memory MCP server for the vault sits outside what these sources discuss (they use CLAUDE.md state sections, markdown notes and memory files; see Section 4).

### Gaps
- No ranking data for most-installed plugins or MCP servers in 2026; marketplace statistics not fetched.
- No practitioner source on Windows-native hook authoring.
- Cherny's page statistics (38 unused skills across 2,345 sessions) lack context.
- Reddit not reachable.

## 3. Which planning and execution workflows do practitioners report work best, and with what results?

### Takeaway
Nearly every named workflow is research, written plan, implement with verification, review, with a human checking the plan and a way for the agent to verify its own work as the highest-leverage item (Cherny estimates 2 to 3x). The split is on ceremony: plan files plus light skills (Tane, Willison, Hashimoto) versus full frameworks, where the independent evidence says the ceremony pays on large multi-file work and wastes tokens on small tasks. Fully unattended loops are reported to fail without human review (Horthy, Ronacher), and no controlled comparison of workflows exists.

### Cited Findings

#### The common shape
- A June 2026 catalog comparing Superpowers, Everything Claude Code, HumanLayer and Spec Kit says all converge on Research, Plan, Execute, Review, Ship, differing only in grouping and naming, and notes it has no measured comparison | [bestagent.dev](https://bestagent.dev/claude-code-workflows-converge-2026) (2026-06-02) [secondary]
- Boris Tane (2026-02-11 [OLD], about nine months of daily use): research.md (a deep read of the relevant code, written to a file he reviews), then plan.md (approach, snippets, file paths, trade-offs, plus a granular todo list), then 1 to 6 annotation cycles in which he edits the plan inline in his editor and tells Claude not to implement yet; then one standard implement prompt (do everything, mark tasks complete in the plan, run typecheck continuously, no needless comments, no `any`); when direction goes wrong he reverts the git changes and re-scopes; all in one long session; he dismisses built-in plan mode and says Ralph loops, MCPs and Gas Town style setups produce messes on non-trivial work | [boristane.com](https://boristane.com/blog/how-i-use-claude-code/) [first-hand, detailed, no measurements]

## 4. How do practitioners keep sessions short and the context clean?

### Takeaway
Three habits coexist: clear between phases and carry state in files (HumanLayer, Shrivu, Paterson, Horthy); work long in one session and rely on a plan file surviving auto-compaction (Tane); or keep many long-lived sessions (Willison). Nearly everyone puts durable state in files, several distrust `/compact`, and the cited thresholds for starting fresh range from 30 to 40 percent of the window up to about 60 percent, all personal rules rather than documented limits.

### Cited Findings

#### Thresholds and when to clear
- Ashley Ha (2025-10-15 [OLD]): never let context pass 60 percent, checked with `/context`; a new conversation starts near 32 percent; clear after research, after planning and after each implement phase | [Ashley Ha, Substack](https://ashleyhaai.substack.com/p/i-mastered-the-claude-code-workflow)
- Horthy (2026-07-15): stay well below the window to avoid the dumb zone: about 300k to 400k on a 1M-token model and about 100k on smaller ones; start a new session when the model repeats mistakes or answers with an agreeable reflex phrase, which signals a poisoned trajectory; use the smartest model first and optimize cost only at real scale | [Pragmatic Engineer](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy)
- rethab on the $100 per month plan keeps context under 30 to 40 percent and occasionally hits the five-hour limit (HN ~May 2026) | [HN item 48289950](https://news.ycombinator.com/item?id=48289950) [anecdote]
- Tane (2026-02-11 [OLD]): saw no noticeable degradation past about half the window, runs research, plan and implementation in one session and relies on the plan file surviving auto-compaction | [boristane.com](https://boristane.com/blog/how-i-use-claude-code/)
- Willison (2026-04-24): keeps about 11 long-lived sessions open and notes that much of his prompting happens in stale ones, which is why a session-clearing bug mattered to him | [simonwillison.net tag page](https://simonwillison.net/tags/claude-code/). Earlier HN advice from roughly and simonw was to start new conversations often because quality degrades well before token limits (HN ~Dec 2025 [OLD]) | [HN item 46256606](https://news.ycombinator.com/item?id=46256606)
- Ask HN replies (~Feb 2026 [OLD]): ckdot clears between unrelated tasks; kpil says a polluted conversation is hard to recover, so restart with a reframed prompt | [HN item 47000206](https://news.ycombinator.com/item?id=47000206)

#### Clear vs compact
- Shrivu (2025-11-02 [OLD]) avoids `/compact` because automatic compaction is opaque and error-prone; default is `/clear` then a custom `/catchup` command that reads the files changed on the branch; for large tasks he uses Document and Clear (write plan and progress to a markdown file, clear, resume from it) | [sshh.io](https://blog.sshh.io/p/how-i-use-every-claude-code-feature)
- Ian Paterson (2026-03-25, updated 2026-08-15) disables auto-compact (`autoCompactEnabled` false in `~/.claude.json` or via `/config`) after it fired at 80 percent mid-refactor and the model lost earlier constraints; he reports about 45k tokens (22.5 percent of a 200k window) is held back as a buffer at the 32k default; his routine is `/flush` (append-only save to a daily log, the project's CLAUDE.md State section, and a memory file), then `/clear`, then `/project` to reload; a custom statusline shows usage; prompt to flush at 60 percent, automatic flush at 85 percent, dump a summary and start fresh above 90 percent | [ianlpaterson.com](https://ianlpaterson.com/blog/stop-claude-code-from-lobotomizing-itself-mid-task/) [first-hand, unmeasured]
- A rule of thumb from a tutorial: if you would not explain the last hour to a new teammate, clear; if a short brief would do, compact, ideally with an instruction saying what must survive | [DEV Community](https://dev.to/stacknotice/claude-code-compact-vs-clear-2026-managing-long-sessions-without-losing-quality-4dhm) [secondary]
- Settings and features mentioned: `showClearContextOnPlanAccept` restores the clear-context choice after approving a plan (anuramat, HN ~mid-2026) | [HN item 48318174](https://news.ycombinator.com/item?id=48318174); skills with `fork: true` run in their own context so heavy skills do not crowd the main session, and an auto-compact window of 400k is mentioned | [howborisusesclaudecode.com](https://howborisusesclaudecode.com) [secondary]; forked agents reuse the prompt cache so side requests stay cheap (Thariq) | [Latent Space](https://www.latent.space/p/thariq)
- Auto memory (Claude's own notes) is per repository, shared across worktrees, and loads the first 200 lines or 25 KB each session | [Claude Code docs: memory](https://code.claude.com/docs/en/memory) (cross-check)

#### Handoff artifacts people actually use
- A plan or todo file that doubles as progress tracker (Tane's plan.md); `thoughts/shared/research` and `thoughts/shared/plans` with dated filenames (HumanLayer via Ha); a markdown progress file for Document and Clear (Shrivu); a State section (working, blocked, next) in the project CLAUDE.md plus daily logs, written by `/flush` and read by `/project` (Paterson); intentional compaction documents (Horthy); a docs/solutions wiki written after each task (Compound Engineering, Section 5); Pocock's newer `/grill-with-docs` is described as writing terminology and decisions into docs as the interview proceeds [secondary, seen in search snippets; exact source page not identified]; other items are sourced as linked elsewhere in this section
- Subagents as context savers: a 2026 analysis calls them among the biggest context savers [secondary]; Majromax on HN says clean-context subagents lower cost; Shrivu prefers cloning the general agent through the built-in Task tool over custom subagents (2025-11-02 [OLD]) | [bestagent.dev](https://bestagent.dev/claude-code-workflows-converge-2026); [sshh.io](https://blog.sshh.io/p/how-i-use-every-claude-code-feature)

#### Making a Max plan last (practitioner statements)
- Willison asked Claude to delegate coding tasks to cheaper subagents to conserve usage of the top model (2026-07-05) and had it save a memory file that routes coding work to lower-tier models while keeping judgment-heavy work in the main model (2026-07-03) | [simonwillison.net tag page](https://simonwillison.net/tags/claude-code/) [first-hand]
- Thariq: users who front-load context (prototype or production, constraints) avoid long rework rounds that burn limits; match effort level to the task (low or medium for UI, high or max for security and review) | [Latent Space](https://www.latent.space/p/thariq) [vendor/author]
- Horthy distinguishes token harder (maxing subscriptions) from token smarter (value while keeping control) (2026-07-15) | [Pragmatic Engineer](https://newsletter.pragmaticengineer.com/p/context-engineering-with-dex-horthy)
- Weaker sources suggest planning with the largest model and executing with a cheaper one, and say Opus draws several times more of the quota than Sonnet | [ClaudeLog](https://claudelog.com/faqs/claude-code-usage-limits/) [secondary, specific numbers unreliable]

### Inferences
- The consistent pattern is state in files, not in the session: any of Tane's plan file, Shrivu's progress file or Paterson's State section works; the user's vault could host the durable version, but no source tests that.
- A visible context meter (statusline) plus a personal threshold is the common mechanism; the right number depends on window size (200k vs 1M) and is a habit, not a documented limit.
- For a weekly-limited plan, the cited levers are cheaper subagents for mechanical work, front-loaded context to avoid rework, and not running ceremony-heavy frameworks on small tasks.

### Gaps
- No measured comparison of `/clear` vs `/compact` outcomes; thresholds are personal rules.
- Paterson cites context-collapse research (arXiv 2510.04618) that I did not review.
- Max-plan specifics rely on weak secondary sources; no heavy-user write-up dedicated to weekly-limit management was found.

## 5. What do practitioners say about community frameworks and mega-configs (Superpowers, SuperClaude, claude-flow, BMAD, GSD, gstack and similar): worth it?

### Takeaway
The evidence is thin and mostly anecdotal. Superpowers has the most real-world scrutiny: it is valued for its brainstorming and review discipline on large multi-file work, and criticized for token overhead and ceremony on small tasks, with one small self-run test showing roughly break-even to modest savings overall. Spec Kit and GSD draw reports of being too heavy; for SuperClaude, claude-flow (now also called Ruflo), BMAD and Everything Claude Code I found no independent critical evaluations, only star counts and promotion. A counter-current prefers small hand-built skills and a minimal setup.

### Cited Findings

#### Superpowers (Jesse Vincent)

#### The minimal and portable counter-current
- Pocock's small skills (see Section 2), Hashimoto's AGENTS.md-plus-scripts harness engineering, Tane's plain markdown files, and NichoPaolucci's return to vanilla plus a few AGENTS.md directives all argue for owning a small visible process over adopting a framework; the combination advice from Particula and zerofuturetech (frameworks for scoping or QA, Superpowers for implementation) is the middle position; sources are linked above.
- Thariq warns that many people build complex harnesses where a simpler one would do (Latent Space, 2026-09-29) | [Latent Space](https://www.latent.space/p/thariq) [vendor/author]

### Inferences
- Popularity (hundreds of thousands of stars) is not outcome evidence; the only measured data are one 12-session self-test and the author's own evals. The defensible reading: adopt a framework piecemeal (for example only the brainstorming interview and the review step), not wholesale, and keep a bypass for small tasks.
- Several of these frameworks assume bash and macOS-first tooling (for example gstack's cookie decryption is macOS-only per Particula); Windows-native behavior is untested in any source I found.
- Because frameworks evolve with model generations (Superpowers 6 and 7 rewrote core pieces within four months), any adopted piece needs the same prune pass as CLAUDE.md.

## 6. AGENTS.md vs CLAUDE.md in 2026: what is the current convention (symlinks, imports, both)?

### Takeaway
Since Claude Code v2.1.277 (announced 2026-09-18) Claude reads AGENTS.md on its own, but only when no CLAUDE.md or CLAUDE.local.md exists in the working directory or any parent; the Anthropic-documented way to share one file across tools is an `@AGENTS.md` import at the top of CLAUDE.md with Claude-only notes below, or the Project instructions setting set to read both. Symlinks still work but are now optional, and carry known bugs and a Windows permission wrinkle.

### Cited Findings

#### Timeline and rules
- Feature request #6235 (opened 2025-08-21) for native AGENTS.md support had 4,407 upvotes and 341 comments and was still open at the time of the July 2026 duplicate; that duplicate, #78977 (2026-07-19), said Claude Code still did not read AGENTS.md and listed workaround bugs: Claude refuses to write CLAUDE.md when it is a symlink (#66559), and `@` imports in ancestor or parent-directory CLAUDE.md files fail to expand or are silently ignored (#78697, #78216) | [claudeissues.com #78977](https://claudeissues.com/issue/78977-feature-request-native-agents-md-support-duplicate-of-6235-filed-deliberately) [issue tracker mirror]
- 2026-09-18: Thariq announced Claude Code supports AGENTS.md from version 2.1.277: if a folder has no CLAUDE.md, Claude checks for and uses AGENTS.md; it ships as a built-in mod | [simonwillison.net, 2026-09-18](https://simonwillison.net/2026/Sep/18/) [vendor/author via Simon's quote]
- Current official rules (fetched 2026-10-24): default setting `claude-md-or-agents-md` reads AGENTS.md only when there is no CLAUDE.md, `.claude/CLAUDE.md` or `CLAUDE.local.md` in the working directory or above; `~/.claude/CLAUDE.md`, managed CLAUDE.md and `.claude/rules/` do not count and keep loading alongside; subdirectory AGENTS.md files load when Claude reads a file there and that folder has none of the three CLAUDE.md variants; `AGENTS.local.md`, `AGENTS.override.md` and anything under `.agents/` are not read; adding a `CLAUDE.local.md` silently stops AGENTS.md from loading. Other `/config` values: `claude-md-and-agents-md` (both, skipping duplicates), `claude-md`, `managed-only`. The setting can be set in `~/.claude/settings.json` under `pluginConfigs` for the built-in plugin `cc-plugin-agents-md@builtin` (earlier ID `agents-md@builtin`, both accepted from v2.1.285) and is ignored in project and local settings. `InstructionsLoaded` hooks do not fire for AGENTS.md read through the setting | [Claude Code docs: memory](https://code.claude.com/docs/en/memory) [vendor/author, cross-check]
- Docs recommendation for sharing one file with other tools: put `@AGENTS.md` on the first line of CLAUDE.md and add Claude-specific instructions below; a `ln -s AGENTS.md CLAUDE.md` symlink also works if no Claude-specific content is needed; remove earlier workarounds (a CLAUDE.md that says in words to read AGENTS.md, or a SessionStart hook that prints it) because they now duplicate content | [Claude Code docs: memory](https://code.claude.com/docs/en/memory)
- A tips site gives the same advice but dates it 2026-06-16, tested on v2.1.281, which conflicts with the 2026-09-18 announcement of v2.1.277; I treat that date as unreliable | [wmedia.es](https://wmedia.es/en/tips/claude-code-agents-md-import-symlink) [secondary, date conflict]. A Towards AI article's 2026-09-18 date matches the announcement but it was paywalled and I did not read it | [Towards AI](https://pub.towardsai.net/agents-md-vs-claude-md-vs-design-md-what-goes-in-which-file-64ea5bc5183a)
- The AGENTS.md site (fetched 2026-10-24) says the format is used by over 60,000 open-source projects, is stewarded by the Agentic AI Foundation under the Linux Foundation, supports nested files where the nearest file wins and explicit user prompts override everything, and lists Codex, Gemini CLI, Cursor, Copilot's coding agent, Amp, Zed, Windsurf and others; Claude Code is not named on the page | [agents.md](https://agents.md) [vendor/spec site]

#### What practitioners do
- Hashimoto's projects use AGENTS.md (including nested ones in Ghostty) as the agent-instruction file (2026-02-05 [OLD]) | [mitchellh.com](https://mitchellh.com/writing/my-ai-adoption-journey)
- An HN user who dropped Superpowers runs near-vanilla Claude with a few directives in AGENTS.md (HN ~Jul 2026); HN commenters pushing for portable, model-agnostic setups note that other tools read AGENTS.md (reactordev, hootz, binary0010, HN ~May 2026) | [HN item 49037528](https://news.ycombinator.com/item?id=49037528); [HN item 48289950](https://news.ycombinator.com/item?id=48289950) [anecdotes]
- Vercel puts its compressed docs index in AGENTS.md (Jan 2026 [OLD]) and ships a codemod to inject it | [Vercel blog](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)
- Pocock-style and Superpowers-style skills target multiple harnesses, so the AGENTS.md plus skills pairing is the portability layer in current practice (see Section 7).

### Inferences
- For a new setup the least fragile pattern per the docs is: AGENTS.md as the shared, tool-neutral file; a small CLAUDE.md whose first line is `@AGENTS.md` followed by Claude-only notes. This also protects against the `CLAUDE.local.md` gotcha and against sessions on older versions or setups that cannot read AGENTS.md directly.
- On Windows, creating a symlink needs Developer Mode or elevated rights, and the symlinked-CLAUDE.md write bug (#66559) means Claude's own edits to it can fail; the import avoids both. This is my inference from the issue list and general Windows behavior, not a sourced recommendation.
- Imports in an ancestor CLAUDE.md had bugs in July 2026 (#78697, #78216); whether September's changes fixed them is unverified, so keep the importing CLAUDE.md in the project root and verify with a canary rule.
- If the user wants other tools (Codex, Gemini CLI, Cursor) to share instructions, AGENTS.md as source of truth is now consistent with both sides; if only Claude Code is used, a plain CLAUDE.md remains simplest.

### Gaps
- Could not read the Towards AI article; could not confirm whether the July 2026 import bugs were fixed.
- No practitioner write-up on running both files with the `claude-md-and-agents-md` setting.
- Whether Windows symlink handling inside Claude Code changed in 2026 is unverified.

## 7. How do the Agent Skills format and cross-tool conventions affect setup choices (Codex, Gemini CLI, Cursor)?

### Takeaway
SKILL.md folders are now a cross-tool format, and prominent practitioners already switch or mix harnesses, so people who care about portability keep shared instructions in AGENTS.md and shared skills in a tool-neutral directory, using only the core frontmatter. The counter-argument on HN is about lock-in to Claude-specific features.

### Cited Findings
- Anthropic published the Agent Skills specification as an open standard at agentskills.io in December 2025, and secondary sources report adoption by OpenAI's Codex, Google's Gemini CLI, GitHub Copilot and Cursor; counts of adopters vary from 25 to 30 or more | [noqta.tn](https://noqta.tn/en/blog/agent-skills-skill-md-universal-ai-coding-standard-2026) [secondary]
- Discovery paths: Cursor documents `.agents/skills/` as a project location and also loads skills from `.claude/skills/` and `.codex/skills/` for compatibility | [Cursor docs](https://www.cursor.com/docs/context/skills). Codex scans repo `.agents/skills/` (current, parent and root directories), user `$HOME/.agents/skills/`, admin `/etc/codex/skills/` and built-ins | [Daniel Vaughan, 2026-05-05, updated 2026-10-24](https://codex.danielvaughan.com/2026/05/05/agent-skills-open-standard-portable-skills-codex-cli-cross-agent/) [secondary]. I did not find Gemini CLI's own docs (see Gaps)

- Harness hopping among respected practitioners: Steinberger prefers Codex for long unattended runs and moved to OpenAI (Pragmatic Engineer, 2026-01-28 [OLD]) | [Pragmatic Engineer](https://newsletter.pragmaticengineer.com/i/185922983/interesting-learnings-from-thow-peter-builds-software); Hashimoto's named tools include Claude Code, Amp and Codex (2026-02-05 [OLD]) | [mitchellh.com](https://mitchellh.com/writing/my-ai-adoption-journey); Ronacher moved from Cursor to mostly Claude Code (2025-12-22 [OLD]) and in Sept to Oct 2026 writes about Pi and Codex without mentioning Claude Code | [lucumr.pocoo.org 2025](https://lucumr.pocoo.org/2025/12/22/a-year-of-vibes/); [lucumr.pocoo.org 2026](https://lucumr.pocoo.org/2026/9/7/astra-why/); Superpowers 6.4 added Meta's Muse, OpenCode 2.0 and Qwen Code (2026-09-21) | [blog.fsck.com](https://blog.fsck.com/)

- Spec Kit supports 15 to 30 plus agents including Claude Code, Cursor, Windsurf and Gemini CLI (tutorial counts vary) | [levelop.dev](https://levelop.dev/blog/github-spec-kit-hands-on-guide) [secondary]

### Inferences
- A low-regret layout: AGENTS.md as the shared instruction file, core-spec skills in a neutral folder (or `.claude/skills/` if only Claude is used, since Cursor also reads it), Claude-only features limited to a thin CLAUDE.md and a few hooks.

## 8. How do solo developers juggle several projects?

### Takeaway
Evidence is thin and mostly about concurrency within one project. The reported patterns: one or a few agents per developer with notifications under the user's control (Hashimoto), several parallel sessions in checkouts or worktrees (Cherny, Steinberger), many long-lived named sessions (Willison), and per-project state files that let a fresh session resume (Paterson). Orchestrator-of-projects tools exist but are unvetted.

### Cited Findings
